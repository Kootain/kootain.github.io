7.2 DTO 与数据验证

7.2 DTO 与数据验证：Class-Validator

在后端开发中，验证 HTTP 请求参数是必修课。

1. DTO (Data Transfer Object)

DTO 是一个纯粹的数据对象，用于定义接口的输入/输出结构。

Go: 通常定义一个 struct，并加上 tag。

type CreateUserRequest struct {
    Email string `json:"email" binding:"required,email"`
    Age   int    `json:"age" binding:"gte=0"`
}

Python (Pydantic):

class CreateUserRequest(BaseModel):
    email: EmailStr
    age: int = Field(ge=0)

NestJS: 使用 class-validator 和 class-transformer。

import { IsEmail, IsInt, Min } from 'class-validator';

export class CreateUserDto {
    @IsEmail()
    email: string;

    @IsInt()
    @Min(0)
    age: number;
}

2. 自动验证管道 (Validation Pipe)

NestJS 提供了一个全局管道，能自动拦截请求，验证 DTO，如果失败直接返回 400 错误。

// main.ts
app.useGlobalPipes(new ValidationPipe({
    whitelist: true, // 自动剔除 DTO 中未定义的属性（防止恶意注入）
    transform: true, // 自动将 payload 转换为 DTO 类的实例
}));

3. 为什么不直接用 Interface？

Interface 在编译后就消失了，无法在运行时做验证。 Class 在编译后依然存在（作为构造函数），配合装饰器元数据，才能实现运行时的校验逻辑。

记住：在 NestJS 中，定义 API 输入参数时，永远使用 Class，不要用 Interface。
