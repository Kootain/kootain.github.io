2.1 结构化类型

2.1 结构化类型 (Structural Typing)

如果说第 1 章是语法的修正，那么第 2 章就是思维的重塑。TypeScript 的类型系统核心是 Structural Typing（结构化类型），俗称“鸭子类型”的静态版。

1. 什么是结构化类型？

"如果它走起来像鸭子，叫起来像鸭子，那么它就是鸭子。" —— 动态语言信条

在 Python 中，这发生在运行时。在 TypeScript 中，这发生在编译时。

[思维映射] 接口实现的隐式性

  • Java/Python (ABC): Nominal Typing (名义类型)。你必须显式继承 class Duck(Animal) 或 implements Duck。
  • Golang: Structural Typing。只要实现了接口的方法，就自动实现了接口。
  • TypeScript: Structural Typing。只要属性结构匹配，类型就兼容。

2. Go vs TypeScript 接口对比

Golang:

type Reader interface {
    Read(p []byte) (n int, err error)
}

type File struct {}
// 不需要显式声明 implements Reader
func (f *File) Read(p []byte) (n int, err error) { return 0, nil }

TypeScript:

interface Reader {
    read(p: Uint8Array): number;
}

class File {
    // 只要有这个方法，TS 就认为它实现了 Reader
    read(p: Uint8Array): number { return 0; }
}

function processReader(r: Reader) { ... }

const f = new File();
processReader(f); // ✅ 合法
processReader({ read: (p) => 0 }); // ✅ 合法！甚至不需要是 File 类的实例

关键点：TS 的接口比 Go 更宽容。Go 要求方法签名完全一致，TS 要求结构兼容（例如：多余的属性通常被允许，缺少的属性报错）。

3. 对象字面量的特殊检查 (Excess Property Checks)

虽然 TS 是结构化类型，但它对直接传入的对象字面量有特殊限制，以防止拼写错误。

interface Config {
    color?: string;
    width?: number;
}

function setup(c: Config) { ... }

// ✅ 正常
setup({ color: "red" });

// ❌ 报错：Object literal may only specify known properties
// 虽然结构化类型允许“多余属性”，但字面量直接赋值被视为“可能是拼写错误”
setup({ color: "red", colour: "red" }); 

// 💡 绕过限制（像 Go 一样强行转换，或者赋值给中间变量）
const myConf = { color: "red", colour: "red" };
setup(myConf); // ✅ 合法！因为 myConf 变量赋值时只检查是否“兼容” Config

4. 总结

对于 Python 开发者，TS 的接口就是 Compile-time Duck Typing。 对于 Go 开发者，TS 的接口就是 Properties-based Interface（Go 是 Method-based）。

记住：TS 关心的是形状 (Shape)，而不是名字。
