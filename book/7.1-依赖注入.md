# 7.1 依赖注入 (Dependency Injection)：NestJS 的核心

NestJS 是 Node.js 生态中最像 Java Spring 的框架。它的核心思想是 **Inversion of Control (IoC)**。

## 1. 为什么需要依赖注入？

在 Go 的 Gin 框架或 Python 的 Flask 中，我们通常手动组装 Service 和 Controller。

**Golang (手动注入):**
```go
func main() {
    db := initDB()
    userService := NewUserService(db) // 手动传入依赖
    server := NewServer(userService)
    server.Run()
}
```

**NestJS (自动注入):**
NestJS 使用 **装饰器 (Decorators)** 来标记依赖关系，由 IoC 容器自动组装。

```typescript
// user.service.ts
@Injectable() // 标记为可被注入的
export class UserService {
    constructor(private db: DBService) {} // 声明依赖
}

// user.controller.ts
@Controller('users')
export class UserController {
    // 容器会自动实例化 UserService 并注入进来
    constructor(private userService: UserService) {}
}
```

## 2. 装饰器 (Decorators) 的魔法

`@Injectable`, `@Controller`, `@Get` 看起来很像 Python 的装饰器。

*   **Python**: 装饰器是运行时修改函数/类的语法糖。
*   **TypeScript**: 装饰器（目前）是实验性特性（需在 `tsconfig.json` 开启 `experimentalDecorators`），它利用反射元数据（Reflection Metadata）来告诉 NestJS 容器如何组装对象。

## 3. Go 开发者视角的对比

Go 社区通常倾向于显式依赖（Explicit Dependency），排斥“魔法”。但在复杂的业务系统中，手动 `NewService(NewRepo(NewDB(...)))` 会变得极其繁琐。

NestJS 提供了类似 Go `Wire` 工具或 `Uber FX` 框架的能力，但体验更顺滑（运行时自动装配，而非代码生成）。

## 4. 模块化 (Modules)

NestJS 强制要求使用 `Module` 来组织代码。

```typescript
@Module({
    imports: [TypeOrmModule.forFeature([User])],
    controllers: [UserController],
    providers: [UserService],
})
export class UserModule {}
```

这类似于 Go 的 `internal` 包隔离，或者 Python 的 `Blueprints`，但提供了更强的边界控制。
