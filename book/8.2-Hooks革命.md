# 8.2 Hooks 革命：副作用管理

在 React 16.8 之前，我们写 Class 组件。现在，我们只写 Function 组件 + Hooks。

## 1. useState: 状态的持久化

函数执行完，变量不就销毁了吗？React 如何保持状态？

```typescript
function Counter() {
    const [count, setCount] = useState(0); 
    // ...
}
```

**原理**：React 内部维护了一个链表，按照 Hooks 调用的顺序存储状态。这有点像闭包。

## 2. useEffect: 副作用与生命周期

这是后端开发者最难理解的部分。

`useEffect` 用于处理 API 请求、订阅事件、DOM 操作等。

```typescript
useEffect(() => {
    // 1. Setup (类似于 Python __enter__ 或 Go init)
    const timer = setInterval(() => { ... }, 1000);

    // 2. Cleanup (类似于 Python __exit__ 或 Go defer)
    return () => {
        clearInterval(timer);
    };
}, []); // 依赖数组
```

### [思维映射]

*   **Go defer**: 函数退出时执行清理。
*   **React useEffect return**: 组件卸载（或依赖变化）时执行清理。

## 3. 闭包陷阱 (Stale Closures)

由于 React 极其依赖闭包，你经常会遇到“读取旧值”的问题。

```typescript
function Watcher() {
    const [count, setCount] = useState(0);

    useEffect(() => {
        const id = setInterval(() => {
            console.log(count); // 永远输出 0！因为这个闭包捕获的是初始时的 count
        }, 1000);
        return () => clearInterval(id);
    }, []); // 依赖数组为空，effect 只运行一次
}
```

**对比 Go Goroutine**:
```go
for i := 0; i < 3; i++ {
    go func() {
        fmt.Println(i) // Go 也有类似的闭包捕获问题（但在 Go 1.22 修复了）
    }()
}
```

**解决**: 将 `count` 加入依赖数组 `[count]`，或者使用 `useRef` (类似于指针) 来保持最新值的引用。
