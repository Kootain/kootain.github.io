# 6.1 Node.js vs Deno vs Bun：三足鼎立？

对于后端开发者，选择运行时（Runtime）是第一步。目前 JS 后端生态呈现“一超多强”的局面。

## 1. 选手介绍

*   **Node.js**: 老牌霸主，生态极其丰富，稳定性最强。
*   **Deno**: Node.js 之父 Ryan Dahl 的悔过之作。内置 TS 支持，安全性高（类似 Android 权限模型）。
*   **Bun**: 后起之秀，用 Zig 编写，主打极速（启动速度、包安装速度）。

## 2. 选型建议

| 维度 | Node.js | Deno | Bun |
| :--- | :--- | :--- | :--- |
| **兼容性** | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐ |
| **生态库** | `npm` 也就是一切 | 自己的 `deno.land` + 兼容 `npm` | 兼容 `npm` |
| **TS 支持** | 需配置 (`tsc`/`ts-node`) | 开箱即用 | 开箱即用 |
| **生产建议** | **首选** | 观望/小型脚本 | 观望/测试环境 |

### [思维映射]

*   **Node.js** = **Python/Golang 标准运行时**。它是工业界的事实标准。
*   **Bun** = **Rust (相对于 C++)**。它很快，很酷，但可能还有未知的坑。

## 3. 为什么我依然推荐 Node.js？

对于刚转型的开发者，不要在工具链上浪费时间。Node.js 拥有最成熟的调试工具、云服务支持（AWS Lambda, Vercel 等）和社区问答。

**配置 TypeScript 运行环境 (Node.js):**

虽然 Node 不能直接跑 TS，但我们可以用 `ts-node` (开发环境) 或 `tsx` (更快的开发环境)。

```bash
# 现代推荐方案：使用 tsx 直接运行 TS 文件
npm install -g tsx
tsx server.ts
```
这就像 Go 的 `go run` 一样方便。
