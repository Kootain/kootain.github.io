# 9.1 服务端渲染 (SSR) 与 静态生成 (SSG)

Next.js 是 React 的元框架，它把 React 从“纯前端”带回了“全栈”。

## 1. 渲染模式光谱

| 模式 | 说明 | 适用场景 | 类比 |
| :--- | :--- | :--- | :--- |
| **CSR (Client-Side Rendering)** | 浏览器下载空白 HTML + 巨大 JS，然后在客户端渲染 | 管理后台、SaaS 面板 | 传统的 Vue/React SPA |
| **SSR (Server-Side Rendering)** | 服务器生成完整 HTML，浏览器直接显示 | 动态内容、SEO 要求高 | Django Template / Go `html/template` |
| **SSG (Static Site Generation)** | 构建时生成 HTML，部署到 CDN | 博客、文档、营销页 | Hugo / Jekyll / Hexo |

## 2. Next.js 的混合渲染

Next.js 的强大之处在于：**你可以为每个页面选择不同的渲染模式**。

*   首页 (Marketing): SSG (极致快)
*   用户中心 (Dashboard): CSR (交互强)
*   新闻详情 (News): SSR (实时性 + SEO)

## 3. Hydration (注水)

后端开发者常问：*“既然 SSR 生成了 HTML，为什么还需要 JS？”*

因为 SSR 生成的 HTML 是“干”的（死的内容）。浏览器加载完 HTML 后，React 会在客户端再次运行，把事件监听器（Click, Submit）绑定到 DOM 上。这个过程叫 **Hydration**。

### [思维映射]

*   **Django**: 生成 HTML 后，如果要有交互，得单独写一段 jQuery/Vanilla JS。
*   **Next.js**: 生成 HTML 和 交互逻辑 的是同一份 React 组件代码。**同构 (Isomorphic)**。

## 4. React Server Components (RSC)

这是 React 18+ 的新概念。

*   **Server Component**: 只在服务端运行。可以直接读数据库！代码不会发送到浏览器（零 Bundle Size）。
*   **Client Component**: 在浏览器运行（也可以在服务端预渲染）。用于处理 `onClick`, `useState`。

```typescript
// app/page.tsx (默认是 Server Component)
import db from './db';

export default async function Page() {
    // 直接读库！就像写 PHP/Go 一样自然
    const users = await db.query('SELECT * FROM users');
    
    return (
        <ul>
            {users.map(user => (
                <li key={user.id}>{user.name}</li>
            ))}
        </ul>
    );
}
```
这对后端开发者来说简直是福音。
