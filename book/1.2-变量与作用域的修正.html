1.2 变量与作用域的修正

1.2 变量与作用域的修正：告别 var

在 Python 和 Go 中，变量定义非常直观。但在 JavaScript 的历史包袱中，var 是一个巨大的坑。作为现代 TS 开发者，请遵循一条铁律：永远不要使用 var。

1. 变量声明对照表

用途 TypeScript Golang Python
不可变绑定 const x = 1 const x = 1 (无原生支持，仅约定)
可变绑定 let x = 1 x := 1 / var x int x = 1
全局/函数作用域 var (禁止使用) 全局变量 全局变量

2. 块级作用域 (Block Scope)

Python 的作用域是函数级的（Function Scope），这意味着 if 块里的变量在块外也能访问。 Go 和 TS (使用 let/const) 都是块级作用域。

Python vs TS

Python:

if True:
    x = 10
print(x) # 输出 10，x 泄漏出了 if 块

TypeScript:

if (true) {
    let x = 10;
    const y = 20;
}
// console.log(x); // Error: Cannot find name 'x'

映射：TS 的 let/const 行为与 Go 的 { } 作用域完全一致。

3. const 的陷阱：引用不可变 vs 值不可变

这是后端开发者最容易混淆的地方。

  • Go: const 必须是编译时常量（数字、字符串）。
  • TS: const 意味着 “变量绑定的内存地址不可变”，但 “地址指向的对象内容是可变的”。

这更像 Python 的变量引用，或者 Go 的指针。

[思维映射] 指针视角

TypeScript:

const user = { name: "Alice" };
user.name = "Bob"; // ✅ 合法！修改的是堆内存中的数据
// user = { name: "Charlie" }; // ❌ 非法！试图修改 user 指向的地址

Golang 等效代码:

// 这里的 const 行为类似 Go 中指针变量本身是不可变的，但指向的 struct 可变
type User struct { Name string }
u := &User{Name: "Alice"} // 假设 u 是一个不可重新赋值的指针
u.Name = "Bob" // 合法

4. 最佳实践

  1. 默认使用 const：95% 的情况下你不需要重新赋值。
  2. 需要修改时用 let：如循环计数器 for (let i=0; ...)。
  3. 遗忘 var：把它扫进历史的垃圾堆。
