3.2 Async/Await 深度解析

3.2 Async/Await 深度解析：Event Loop 的真相

async/await 是 Promise 的语法糖，它让异步代码看起来像同步代码。但这背后隐藏着 JS 与 Go 本质的并发模型差异。

1. 单线程 vs 多线程

这是后端开发者转型 Node.js 最大的认知门槛。

  • Golang (Goroutine): 多线程并行 (Parallelism)。Go Runtime 将成千上万个 Goroutine 映射到多个 OS 线程上，利用多核 CPU。
  • Node.js (Event Loop): 单线程并发 (Concurrency)。主线程只有一个，通过非阻塞 I/O 来处理高并发。

[比喻] 餐厅模型

  • Go 餐厅: 雇佣了 10 个服务员（线程）。如果一个客人点菜慢，该服务员等待，其他服务员继续服务别的桌。
  • Node.js 餐厅: 只有 1 个 超级服务员（主线程）。他语速极快，点完菜扔给厨房（系统内核/线程池）就立马去下一桌。厨房做好后按铃（Callback），服务员再把菜端上去。

结论: Node.js 不适合 CPU 密集型 任务（如视频转码、复杂计算），因为这会阻塞唯一的服务员。Node.js 极度适合 I/O 密集型 任务（如 API 网关、数据库 CRUD）。

2. Async/Await 的执行顺序

Python (asyncio): Python 的 async 也是单线程 Event Loop，但需要显式的 Loop 启动。

TypeScript:

console.log("1");

async function demo() {
    console.log("2");
    await new Promise(r => setTimeout(r, 0)); // 宏任务
    console.log("4");
}

demo();
console.log("3");

// 输出顺序: 1 -> 2 -> 3 -> 4

解析:

  1. demo() 被调用，同步执行直到遇到 await。
  2. await 暂停了 demo 函数的执行，主线程跳出函数继续执行 "3"。
  3. 这里的 await 相当于让出了控制权（Yield）。

3. 宏任务与微任务 (Macro vs Micro Tasks)

这是面试必考题，也是理解执行顺序的关键。

  • 微任务 (Microtasks): Promise.then, queueMicrotask。优先级高，本轮循环结束前插队执行。
  • 宏任务 (Macrotasks): setTimeout, setInterval, I/O 回调。优先级低，下一轮循环执行。

Go 开发者: Go 没有这个区分，调度器是非确定性的。但 JS 的 Event Loop 顺序是严格确定的。

4. 总结

  • TS 的 async/await 让你写出类似 Go 的同步风格代码。
  • 警惕阻塞: 永远不要在 Node.js 主线程写死循环或重计算。
  • 并发控制: 使用 Promise.all 并发请求，不要在一个 for 循环里傻傻地 await（串行化了）。
