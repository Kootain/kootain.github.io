# 7.3 ORM 选型：Prisma vs TypeORM

TS 领域的 ORM 经历了从 TypeORM (类 Hibernate/Java JPA) 到 Prisma (类 Rust Diesel/Go sqlc) 的演进。

## 1. TypeORM：老派的选择

TypeORM 模仿了 Java 的 Hibernate。它使用装饰器将 Class 映射到数据库表。

```typescript
@Entity()
export class User {
    @PrimaryGeneratedColumn()
    id: number;

    @Column()
    name: string;
}
```

**缺点**：类型安全依赖于手写 Class，容易与数据库实际结构脱节。

## 2. Prisma：现代的选择

Prisma 是目前 TS 生态最热门的 ORM。它的核心理念是 **Schema First**。

**workflow:**
1.  编写 `schema.prisma` (类似 Go 的 struct 或 SQL DDL)。
2.  运行 `prisma generate` 生成 TS 类型定义。
3.  在代码中使用生成的 Client。

**schema.prisma:**
```text
model User {
  id    Int     @id @default(autoincrement())
  email String  @unique
  posts Post[]
}
```

**TS Code:**
```typescript
// 这里的 User 类型是 Prisma 自动生成的，与 DB 严格同步
const user = await prisma.user.create({
    data: {
        email: "alice@prisma.io",
    },
});
```

## 3. 对比 Golang

*   **Prisma** 类似于 **sqlc** 或 **ent**。它们都侧重于“代码生成”来保证类型安全。
*   **TypeORM** 类似于 **GORM**。侧重于运行时反射和动态构建 SQL。

## 4. 建议

对于新项目，**强烈推荐 Prisma**。它提供的类型提示（Intellisense）是无与伦比的。你不需要看文档就知道 `user` 有哪些字段，关联查询怎么写。
