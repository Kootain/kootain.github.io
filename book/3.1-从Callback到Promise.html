3.1 从 Callback 到 Promise

3.1 从 Callback 到 Promise：拯救回调地狱

在 ES5 时代，JavaScript 的异步处理是噩梦般的（回调地狱）。但 ES6 引入的 Promise 彻底改变了游戏规则。

1. 什么是 Promise？

Promise 是一个状态机，它代表一个未来可能完成（或失败）的异步操作。

它有三种状态：

  1. Pending (进行中)
  2. Fulfilled (已成功) -> 携带 Value
  3. Rejected (已失败) -> 携带 Error

[思维映射] Future/Task

  • Python: 类似于 asyncio.Future 或 Task。
  • Golang: 类似于一个只读的 <-chan Result，你等待它返回结果。

2. 链式调用 (Chaining)

Promise 的核心在于 .then()，它允许我们将异步操作串联起来，形成扁平的代码流。

// 模拟一个异步操作
function getUser(id: number): Promise<User> {
    return new Promise((resolve, reject) => {
        setTimeout(() => {
            if (id > 0) resolve({ id, name: "Alice" });
            else reject(new Error("Invalid ID"));
        }, 1000);
    });
}

// 链式调用
getUser(1)
    .then(user => {
        console.log("Got user:", user);
        return getUserPosts(user.id); // 返回下一个 Promise
    })
    .then(posts => {
        console.log("Got posts:", posts);
    })
    .catch(err => {
        // 捕获链路上任何一个步骤的错误
        console.error("Error:", err);
    });

对比 Go: Go 使用阻塞式写法（看起来同步，实际由 Runtime 调度），错误通过多返回值处理。 JS 的 Promise 则是显式的异步容器，错误通过 .catch 冒泡处理。

3. Promise.all vs WaitGroup

当需要并发执行多个任务时：

Golang (WaitGroup):

var wg sync.WaitGroup
wg.Add(2)
go func() { defer wg.Done(); task1() }()
go func() { defer wg.Done(); task2() }()
wg.Wait()

TypeScript (Promise.all):

const [res1, res2] = await Promise.all([task1(), task2()]);

Promise.all 更加声明式：只有当所有 Promise 都成功时才 Resolve，任意一个失败则 Reject。这类似于 Python 的 asyncio.gather()。
