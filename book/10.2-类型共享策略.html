10.2 类型共享策略

10.2 类型共享策略：全栈开发的圣杯

TS 全栈开发最核心的优势就是：Single Source of Truth (单一真实信源)。

1. 传统的痛点

  1. 后端修改了 DB 字段 name -> fullname。
  2. 后端 API 变了。
  3. 前端不知道，继续用 name。
  4. 上线，前端报错，用户投诉。

2. 共享类型的实现

在 Monorepo 中，我们可以创建一个 packages/shared-types 包。

packages/shared-types/index.ts:

export interface User {
    id: number;
    fullname: string; // 后端修改了这里
    role: 'admin' | 'user';
}

apps/api (Backend):

import { User } from '@repo/shared-types';

function getUser(): User {
    return { id: 1, fullname: "Alice", role: "admin" }; // ✅ 必须匹配接口
}

apps/web (Frontend):

import { User } from '@repo/shared-types';

function UserProfile({ user }: { user: User }) {
    return <div>{user.name}</div>; 
    // ❌ Error: Property 'name' does not exist on type 'User'. Did you mean 'fullname'?
}

3. 效果

当你修改了共享包里的类型定义：

  1. 编辑器（VS Code）会立即变红，指出所有受影响的前端和后端代码。
  2. tsc 编译会失败，阻止你上线。

这就是 Refactoring Confidence (重构信心)。这是 Python/Go 前后端分离模式（通过 Swagger/JSON 同步）很难达到的境界。
