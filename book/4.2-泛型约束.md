# 4.2 泛型约束：给类型加个紧箍咒

如果泛型 `T` 可以是任何类型（`any`），那我们能对它做的操作就很少（只能做所有类型通用的操作）。为了使用特定属性（如 `.length` 或 `.id`），我们需要对 `T` 进行约束。

## 1. extends 关键字

在 TS 中，`extends` 不仅仅用于类继承，更用于 **泛型约束 (Generic Constraints)**。

**场景**：编写一个函数，打印任何带有 `.length` 属性的对象的长度。

**TypeScript:**
```typescript
interface Lengthwise {
    length: number;
}

// T 必须包含 Lengthwise 定义的结构
function logLength<T extends Lengthwise>(arg: T): T {
    console.log(arg.length); // ✅ 合法，因为 T 被约束了
    return arg;
}

logLength("hello"); // ✅ string 有 length
logLength([1, 2]);  // ✅ array 有 length
logLength(3);       // ❌ number 没有 length
```

### [思维映射]

*   **Golang**: Interface Constraints.
    ```go
    type Lengthwise interface {
        Len() int
    }
    func LogLength[T Lengthwise](arg T) { ... }
    ```
*   **Python**: `TypeVar("T", bound=Lengthwise)`。

## 2. 在 keyof 中使用约束

这是 TS 极其强大的模式，用于实现类型安全的属性访问。

```typescript
// K 必须是 obj 键名的子集
function getProperty<T, K extends keyof T>(obj: T, key: K) {
    return obj[key];
}

const x = { a: 1, b: 2, c: 3 };

getProperty(x, "a"); // ✅ 返回 number
getProperty(x, "d"); // ❌ 编译错误：Argument of type '"d"' is not assignable to parameter of type '"a" | "b" | "c"'
```

**对比 Golang**: Go 很难在编译时实现这种“字段名检查”。你通常需要使用反射（Runtime），或者代码生成。TS 在编译阶段就拦截了此类错误。

## 3. 泛型约束实战：简易 ORM 签名

```typescript
interface BaseModel {
    id: string;
}

class User implements BaseModel {
    id: "user_1";
    name: "Alice";
}

// T 必须是 BaseModel 的子类
function findById<T extends BaseModel>(model: new () => T, id: string): T {
    // ... db query ...
    return new model();
}
```

## 4. 总结

*   `T` 就像一个变量，只不过存的是类型。
*   `extends` 就像给这个变量加了类型注解，限制了它的取值范围。
*   掌握 `keyof` 约束是通往高级 TS 的必经之路。
