2.3 字面量类型与枚举

2.3 字面量类型与枚举：最佳实践

TypeScript 中有两种定义“一组常量”的方式：Enum 和 Literal Types。 对于后端开发者，我的建议非常直接：尽可能使用 Literal Types，慎用 Enum。

1. 字面量类型 (String Literal Types)

TS 允许将字符串本身作为一个类型。

// 定义一个类型，它只能是这三个字符串中的一个
type HttpMethod = 'GET' | 'POST' | 'DELETE';

function request(url: string, method: HttpMethod) { ... }

request("/api", "GET"); // ✅
request("/api", "PUT"); // ❌ Error: Argument of type '"PUT"' is not assignable...

[思维映射]

  • Python: Literal['GET', 'POST'] (typing 模块)。
  • Golang: 定义一堆 const，然后定义一个自定义类型别名。
    type Method string
const (
    GET  Method = "GET"
    POST Method = "POST"
)

2. 枚举 (Enums) 的坑

TypeScript 的 enum 是少数几个不是 JavaScript 语法糖的特性之一。这意味着 enum 会在编译后生成额外的运行时代码（一个反向映射对象）。

TypeScript Enum:

enum Status {
    Open,
    Close
}

编译后的 JS (哪怕是 ESNext 目标):

var Status;
(function (Status) {
    Status[Status["Open"] = 0] = "Open";
    Status[Status["Close"] = 1] = "Close";
})(Status || (Status = {}));

这不仅增加了包体积，而且违背了 TS “只做类型擦除”的初衷。

3. 现代最佳实践：联合字面量

使用 type + | 是更轻量、更符合 TS 哲学的做法。

// 推荐写法
type Status = 'open' | 'close';

// 如果需要运行时迭代（例如生成下拉菜单），结合 const assertions
const STATUS_LIST = ['open', 'close'] as const;
type StatusType = typeof STATUS_LIST[number]; // 自动推导出 'open' | 'close'

4. 总结

  • 如果你习惯了 Go 的 const 组，请在 TS 中使用 Union Literal Types ('A' | 'B')。
  • 它编译后为零运行时开销（字符串还是字符串）。
  • 它能享受 IDE 的完整自动补全。
