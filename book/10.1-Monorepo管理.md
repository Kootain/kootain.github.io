# 10.1 Monorepo 管理：Turborepo 与 Pnpm

随着项目变大，你可能有了 `web` (前端), `api` (后端), `docs` (文档) 等多个项目。Monorepo 是将它们放在一个 Git 仓库中管理的策略。

## 1. 为什么需要 Monorepo？

*   **原子提交 (Atomic Commits)**: 一次 Commit 同时修改前后端代码，保证版本同步。
*   **代码复用**: 提取公共的 `utils`, `types`, `ui-components` 到独立的包中，供前后端共享。

## 2. 工具选型：Pnpm Workspaces + Turborepo

*   **Pnpm Workspaces**: 解决依赖安装和链接问题（类似 Go Workspace）。
*   **Turborepo**: 解决构建缓存和任务编排问题（类似 Bazel 但更简单）。

**目录结构示例:**

```text
/apps
  /web (Next.js)
  /api (NestJS)
/packages
  /ui (Shared React Components)
  /database (Prisma Schema & Client)
  /tsconfig (Shared TypeScript Config)
```

### [思维映射]

*   **Golang**: `go.work` (Go 1.18+) 允许在本地同时编辑多个 Module。
*   **Python**: 通常用 Poetry 或 virtualenv，Monorepo 支持较弱（Pants/Bazel 门槛高）。TS 生态的 Monorepo 工具链非常成熟。

## 3. 任务编排

Turborepo 允许你定义任务依赖。例如：`build` 依赖于 `test`。

```json
// turbo.json
{
  "pipeline": {
    "build": {
      "dependsOn": ["^build"], // 依赖于上游包的 build
      "outputs": ["dist/**"]
    }
  }
}
```

当你运行 `turbo build`，它会智能地并行构建所有应用，并利用缓存（如果文件没变，直接复用上次构建结果）。
