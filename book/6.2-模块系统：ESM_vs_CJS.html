6.2 模块系统：ESM vs CJS

6.2 模块系统：ESM vs CJS 的战争

这是 JS 历史上最大的分裂，也是新手最容易踩的坑。

1. 历史包袱：CommonJS (CJS)

在 Node.js 诞生之初（2009），JS 没有模块标准。Node 发明了 require。

// CJS
const fs = require('fs');
module.exports = function() {};

2. 现代标准：ECMAScript Modules (ESM)

2015 年，ES6 标准确立了 import/export。

// ESM
import fs from 'node:fs';
export default function() {};

[思维映射]

  • Python: import os (ESM 风格)。
  • Golang: import "fmt" (ESM 风格)。
  • CJS: 类似于 Python 的动态导入 __import__('module')，它是运行时加载的。

3. 痛点：Dual Package Hazard

很多 npm 包同时提供了 CJS 和 ESM 版本，或者只提供其中一种。混用时会报错： Error: require() of ES Module ... not supported.

4. 最佳实践：全栈 ESM

在 2024 年+，请默认使用 ESM。

如何开启 ESM？

在 package.json 中添加：

{
  "type": "module"
}

一旦开启，你的 .js 文件默认被视为 ESM。如果你必须写 CJS，文件后缀改为 .cjs。

TypeScript 的配置 (tsconfig.json):

{
  "compilerOptions": {
    "module": "NodeNext", // 或 "ESNext"
    "moduleResolution": "NodeNext"
  }
}

结论：哪怕遇到阻力，也要坚持使用 import/export。这是未来的标准，也是 Tree Shaking（死代码消除）的基础。
