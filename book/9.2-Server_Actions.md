# 9.2 Server Actions：RPC 的文艺复兴

在传统的前后端分离模式中：
1.  后端写 API (FastAPI/Gin)。
2.  定义 OpenAPI/Swagger。
3.  前端生成 Client 代码。
4.  前端调用 `axios.post('/api/user')`。

Next.js 的 **Server Actions** 把这个过程简化到了极致。

## 1. 什么是 Server Actions？

你可以在前端组件里，直接 import 一个后端函数并调用。Next.js 编译器会自动把它变成一个 HTTP POST 请求。

```typescript
// actions.ts (服务端代码)
'use server'; // 标记为 Server Action

export async function createUser(formData: FormData) {
    const name = formData.get('name');
    await db.user.create({ data: { name } });
    return { success: true };
}
```

```typescript
// form.tsx (客户端代码)
'use client';
import { createUser } from './actions';

export function RegisterForm() {
    return (
        <form action={createUser}>
            <input name="name" />
            <button type="submit">Sign Up</button>
        </form>
    );
}
```

## 2. End-to-End Type Safety

这是 Python/Go 很难做到的。

如果你修改了 `createUser` 的参数签名，前端调用处会**立即**报 TS 编译错误。
你不需要 OpenAPI，不需要代码生成，不需要维护两份类型定义。

## 3. 对比 RPC

这本质上就是 RPC (Remote Procedure Call)。

*   **gRPC**: 需要 `.proto` 文件定义契约。
*   **Server Actions**: **TypeScript 就是契约**。

## 4. 总结

对于全栈开发者，Server Actions 极大地缩短了“想法 -> 实现”的路径。你不再需要为了一个简单的 CRUD 去写整套 RESTful API。
